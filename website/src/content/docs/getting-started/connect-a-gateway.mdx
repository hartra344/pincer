The first time you open Pincer, it walks you through connecting to your OpenClaw Gateway. You'll find the gateway, sign in, approve this device, and finish with a quick [setup](../setup-wizard/) of your default agent. Every step has **Back**, and the progress bar at the top shows where you are. If you quit partway through, Pincer picks up where you left off.

You can start the same flow any time with **Add Gateway…**: click **+** in the rail, use the menu bar, or press <kbd>⌘</kbd> <kbd>K</kbd> and choose **Add Gateway…**.

## 1. Welcome

Choose **Get Started**. To look around first, choose **Try the Demo** instead (see [Try the demo](../try-the-demo/)).

## 2. Do you have a gateway?

Pincer connects to a Gateway you run on your own computer or server. It never runs one itself.

- **Yes, it's running** goes to the next step.
- **No, help me set one up** shows the commands below. Run them on the computer that will host your gateway, then choose **My Gateway Is Running**.

<Steps>
1. Install OpenClaw. Follow the prompts and choose **Quick start**.

   <Tabs>
     <TabItem label="macOS / Linux">
       ```sh
       curl -fsSL https://openclaw.ai/install.sh | bash
       ```
     </TabItem>
     <TabItem label="Windows">
       ```powershell
       iwr -useb https://openclaw.ai/install.ps1 | iex
       ```
     </TabItem>
   </Tabs>

2. Keep the gateway running in the background:

   ```sh
   openclaw gateway install
   ```

3. Check that it's working. It should say it's listening on port 18789:

   ```sh
   openclaw gateway status
   ```
</Steps>

The full guide is OpenClaw's [Getting started](https://docs.openclaw.ai/start/getting-started).

## 3. Find your gateway

Tell Pincer where OpenClaw is running:

| Choice | When to use it | Address |
| --- | --- | --- |
| **This Mac** (macOS only) | OpenClaw runs on the Mac you're using. | Filled in for you: `ws://127.0.0.1:18789` |
| **Tailscale** | Your gateway is on another device in your tailnet. The easiest way to reach it from an iPhone. | `wss://my-mac.tail1234.ts.net` |
| **Same Wi-Fi** | Your gateway is on this network and set to accept connections from it. | `ws://192.168.1.20:18789` |

You can type just the host name or IP. Pincer fills in the rest and shows the full address it will use, such as *Pincer will connect to wss://my-mac.tail1234.ts.net*.

For Tailscale, turn on Tailscale Serve on the gateway host first. The gateway stays private to your tailnet:

```sh
openclaw config set gateway.tailscale.mode serve
openclaw gateway restart
```

More in [Connect over Tailscale](../tailscale/).

If your gateway announces itself on your network, it also shows up under **Nearby**. Choose it to fill in the address. You still sign in in the next step.

Choose **Continue**. Pincer checks that it can reach the gateway before moving on. If it can't, it tells you why. See [If something goes wrong](#if-something-goes-wrong).

## 4. Sign in

Paste your gateway's **token**. To see it, run this on the gateway host:

```sh
openclaw config get gateway.auth.token
```

If your gateway uses a password, choose **Use a password instead**. To see it:

```sh
openclaw config get gateway.auth.password
```

Choose **Sign In**. You only need to do this once per device. Pincer keeps the secret in the Keychain.

## 5. Approve this device

For your security, the gateway has to approve each new device once. Pincer shows the exact command to run on the gateway host, with **Copy Command**:

```sh
openclaw devices approve <requestId>
```

While it waits, Pincer shows **Waiting for approval…** and moves on by itself as soon as you approve it. If the request ID changes, for example after you reject a request, Pincer shows the new command. To see every pending request:

```sh
openclaw devices list
```

<Aside type="tip">
Every Mac, iPhone and iPad has its own device key, so each needs to be approved once. After that, it reconnects on its own.

Pincer can't approve its own first pairing, so the first device always needs the host. After that, a device paired with Full Management can approve your other devices from Gateway Settings → Devices. See [Devices & Nodes](../../guides/devices/).
</Aside>

## 6. You're connected

Pincer shows the gateway's name, its version, and what this device can do. You can change the **Name** Pincer uses for it.

If the gateway reports a health problem, you'll see a note with **Details**. It doesn't stop you from continuing.

If it says **Full Management** isn't on: Full Management lets Pincer change gateway settings and agents. You don't need it to chat. You can turn it on later in **Gateway Settings → Connection** (see [Access levels](#access-levels)).

Choose **Continue Setup** to pick your default agent and send a test message (see [Set up a gateway](../setup-wizard/)), or **Skip to Chats** to start chatting. Either way, you land in your chat list with the new gateway selected.

## If something goes wrong

| What Pincer says | What to do |
| --- | --- |
| "That doesn't look like a Gateway address." | Check the address. It should look like `wss://my-mac.tailnet.ts.net` or `ws://192.168.1.20:18789`. |
| "For safety, Pincer only uses unencrypted ws:// on this Mac, your local network, or Tailscale." | Use a `wss://` address, such as Tailscale Serve. |
| "Can't reach a Gateway at that address." | Make sure OpenClaw is running (`openclaw gateway status`) and that this device can reach it. For Tailscale, check that Tailscale is connected on this device. |
| "Something answered, but it isn't an OpenClaw Gateway." | Check the address and port. The default port is 18789. |
| "Couldn't make a secure connection to that address." | If you use Tailscale Serve, check that HTTPS is enabled for your tailnet. |
| "That token didn't work." | Run `openclaw config get gateway.auth.token` again and paste the whole thing. |
| "That password didn't work." | Check the password and try again. |
| "This Gateway isn't set up for that sign-in method." | Switch between token and password. |
| "Too many tries." | Wait a minute, then try again. |
| "This Gateway's version doesn't work with this Pincer." | Update OpenClaw or Pincer. |
| "The Gateway turned down this device." | Go back and try again, or approve the request with the command shown. |

More in [Troubleshooting](../../reference/troubleshooting/).

## Advanced connection settings

Most people never need these. Choose **Advanced…** on the **Find your gateway** step to open the full connection form, or change them later under **Gateway Settings → Connection** (**Edit Connection**).

<DocScreenshot src={connection} alt="Connection form for Local Mock at ws://127.0.0.1:19879 with a masked token and Full Management selected." caption="Local development example, not a production address. Use your own gateway address and access level." narrow />

| Field | What it's for |
| --- | --- |
| **Authentication** | Also offers *Tailscale identity / none* for gateways that don't use a token or password. |
| **Access** | *Chat & Approvals* for everyday use, or *Full Management* to also edit gateway settings. |
| **TLS certificate SHA-256** | Pins the gateway's certificate by its fingerprint. If it doesn't match, Pincer says "The Gateway's certificate doesn't match the fingerprint you entered." |

Plain `ws://` is only allowed for loopback, private LAN and Tailscale addresses. Anything else has to use `wss://`.

### Access levels

| Level | Scopes | What you can do |
| --- | --- | --- |
| **Chat & Approvals** (default) | `operator.read`, `operator.write`, `operator.approvals`, `operator.questions` | Chat, read history, answer approvals and agent questions, and see Approval History. Gateway settings are read-only. |
| **Full Management** | Also `operator.admin` | Also change the gateway's settings and plugins. |

Switching to **Full Management** asks the gateway for more access, so the gateway host needs to approve the device again.

## Where your secrets go

Tokens and passwords are stored in the **Keychain**, never in preferences. The device identity is an Ed25519 key, also in the Keychain and marked *this device only*, so it doesn't sync to other devices. More in [Security & privacy](../../reference/security/).

## Turn on thinking

OpenClaw only stores the agent's reasoning when the session's reasoning level is on. To see it in Pincer, use the hint above the composer, choose **Gateway Reasoning → Save & Stream** from the chat's ⋯ menu, or send:

```text
/reasoning on
```

See [Transcript, thinking & tools](../../guides/transcript/) for how much of it to show.
